## 14. Aprendizaje técnico

- Un servidor MCP project-scoped que muestra `Pending approval` en una sesión no
  tiene sus tools cargadas ni siquiera como *nombres* diferidos completos — solo tras
  la aprobación (que ocurre al arrancar una sesión interactiva nueva) aparecen como
  tools reales invocables. La forma más confiable de confirmar "conectado de verdad"
  no es leer el texto de `claude mcp get`, sino **cargar el schema real vía
  `ToolSearch` e invocarlo** — un servidor pendiente no puede ofrecer eso.
- La detección de modo headless por string de user-agent es una técnica obsoleta
  contra Chrome moderno: el modo `headless=new` (desde Chrome ~112) deja de anunciarse
  como tal deliberadamente para reducir el fingerprinting de bots, así que ausencia de
  `HeadlessChrome` en el UA ya no implica modo headed.
- Herramientas MCP externas pueden tener efectos secundarios en el filesystem del
  repo que ni `.gitignore` ni `.prettierignore` anticipan (acá, snapshots
  auto-guardados en `.playwright-mcp/`) — al integrar cualquier MCP nuevo conviene
  correr `git status` inmediatamente después de la primera invocación real, no asumir
  que una tool de "solo lectura" (navegar, ver snapshot) no toca disco.
- Cuando `npm run quality` encadenado falla, aislar cada gate (`typecheck`, `lint`,
  `format:check`, `test:unit` por separado) permite distinguir un problema real del
  código de un problema de un archivo ajeno al scope — evita reportar un falso "quality
  rojo" cuando en realidad los tres checks que importan pasan limpio.
